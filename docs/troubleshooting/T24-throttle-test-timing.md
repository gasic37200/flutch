# 게이지 묶음 시나리오가 전체 테스트에서만 실패 (시간 기준점)
- task: T24 · PR: (이 PR) · 날짜: 2026-11-10
- 영역: backend/tests (clutch)

## 증상
`clutch_gauge_event_throttled` 첫 버전이 `cargo test --test scenarios clutch` 단독으로는 매번 통과하는데, 전체 `cargo test`에서 "두 번째 `clutch.gauge`가 첫 이벤트 뒤 350ms 이상" 단언으로 실패.

## 원인
기준 시각 `t0`를 **첫 이벤트를 받은 뒤**에 쟀다. 테스트는 HTTP 클러치 3번(사이에 점수 시드)을 끝낸 다음에야 첫 이벤트를 읽으므로, 부하가 크면 실제 발행 시각보다 `t0`가 수백 ms 늦어진다. 서버는 첫 발행 + 500ms에 정확히 보냈지만 `t0` 기준으로는 짧아 보였다. 같은 이유로 "클러치 3번이 500ms 안에 끝난다"는 가정도 부하에서 깨질 수 있었다.

## 해결
- `t0`는 첫 클러치 요청 **전에** 잰다(발행 시각 ≥ `t0`라 "≥ 500ms"가 부하와 무관하게 참).
- 간격 안의 게이지 2개는 HTTP가 아니라 `clutch::publish`를 직접 연달아 불러(마이크로초 간격) 묶임을 결정적으로 만든다. 실제 경로(HTTP 클러치 → 즉시 발행)는 첫 이벤트와 다른 앱 인스턴스 쪽에서 확인.

## 재발 방지
시간 간격 단언은 "서버가 행동한 시각보다 앞선" 기준점에서 잰다. 이벤트 수신 시각을 기준으로 쓰지 않는다. 묶음·디바운스 테스트는 입력을 부하와 무관하게 몰아 넣는다.
